# Overall coverage stays enforced when CI is incremental

André approved the coverage policy and measurement seams on 2026-10-31, then explicitly required the same policy in incremental CI with nightly whole-repository checks. Spec §5.4 owns the acceptance contract; `.superman/ci/coverage.json` is the protected executable policy. A changed-files percentage or a previous passing average cannot establish the current overall result: denominators change, and changed tests can invalidate coverage of unchanged code.

Incremental enforcement therefore requires fresh affected-code measurements plus verified unchanged-code evidence over the exact complete inventory. It must bind source, tests, dependency/selection model, effective configuration, tool/instrumentation identities and producer provenance. Unknown or stale evidence invokes uncached full verification; nightly always remeasures everything. The bootstrap has no trusted coverage ledger/selector, so it deliberately uses that full fallback rather than activating future cache/provider tickets.

**Current Node-specific implementation/evidence:** Vitest alone would omit the Node bootstrap subprocesses and the rules running inside Archgate's Bun binary. Exact-pinned development tools measure disjoint inventories and aggregate counts. Supplemental exported-rule callback tests make actual rule code measurable; they do not replace the pinned-engine process fixtures or prove parser integration. c8's locked V8 merger/Istanbul reporters, Vitest's public test API and its locked AST converter/Vite parser remain the bounded development-tool API exception to ADR 0003, not product runtime dependencies. No additional dependency is installed for conversion.

Independent review demonstrated that c8's synthetic uncovered-file report counted one function even when an unloaded module declared 100. Native Node V8 data is therefore converted against the AST of **every** inventoried file, with Node's native strip-only transformation preserving source offsets; missing execution data supplies zero hits, not a synthetic denominator. Unsupported source-map directives block rather than substituting different source content. Vitest receives an explicit empty method-exclusion list and returns its coverage over an owned pipe; only the parent validates inputs/aliases and publishes reports. This closes demonstrated method-exclusion and report-symlink false evidence without excluding runtime code.

**Deno amendment, interview-confirmed but unimplemented (2026-11-01, ADR 0016):** the current Node offsets/collector/receipt cannot establish coverage of Deno execution. Before product admission, separately authorized Gate 1 work must prove exact executed-source/transpilation mapping, complete executed **and unloaded** Deno/retained-Node-driver/rule inventories and correct independent line/statement/branch/function counts using the retained dev-only tools. Deno's native three-metric report and Vitest's Node-child option are not that proof. Missing/stale/partial profiles, child timeout/crash, alias/double-counting or unsupported mapping fail visibly; suppression-family enforcement includes Deno coverage-ignore directives. Fresh owned per-worker collection and adversarial zero/partial-hit fixtures must pass on all three native platforms. Canonical measurements run the Deno source route; exact compiled artifacts additionally run the public conformance suite with source/build/runtime/permission bindings, not a claim of collected binary coverage. Historical measurements keep their original revision/platform scope. No floor, source inventory or provenance requirement is weakened; reuse stays off until separately proved activation.

The confirmed quality amendment (Q31/Q35, ADR 0017) retains all four independent 90% floors and the 100% target, including the operational enforcement core and unloaded files. Dynamic counters remain bounded evidence, not tamper-proof program-correctness proof. No incomplete/missing data is accepted because of that limit. Exact critical scope/mutation mappings require their own evidence; they do not create a new per-file coverage floor.

The separately completed [SUP-005 preparation](../../.scratch/superman-v0/gate1-preparation.md) prevents its declared Deno comment namespace under the current evaluator. Its passing frozen-fixture receipt is Node/darwin-arm64 supporting evidence with no merge authority; the standalone collector was not changed and no Deno collection was exercised. Preserve that distinction and the earlier changed-input/dirty-driver refusals rather than calling suppression fixtures a complete Deno coverage pass.

Per-file floors and an automatic threshold ratchet were not selected: overall coverage is the requirement, and the 100% target must not become a reason to omit difficult code. The protected collector and required CI jobs enforce the policy directly, not through an editable package script. Remote self-hosted CI and Gate 1 approval remain separate evidence; a local coverage receipt grants no merge authority.
