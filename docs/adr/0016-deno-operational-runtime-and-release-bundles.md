# Deno operational runtime and v0 release bundles, without replacing quality tools

André confirmed this design and testing seams on 2026-11-01 ([interview Q4/Q6–Q19 and follow-up Q20–Q24](../../.scratch/superman-v0/deno-amendment.md)). Deno will run Superman's CLI, hooks, owned bootstrap/verifiers/orchestration and later protected writers. Real Node/pnpm remain development-tool hosts with bounded test/measurement-driver exceptions. Keep tsrs, Vitest, Stryker, Biome and approved measurement libraries: a runtime choice is not a toolchain replacement. Spec §5.10 owns runtime policy, §12 distribution and §17 admission prerequisites.

V0 requires a versioned source/assets release and Deno-compiled binaries for macOS arm64, Linux x64 and Linux arm64; it has **no npm/npx distribution or npm publisher**. One canonical on-disk skill tree remains shared by the three harnesses. The compiled CLI needs no separately installed Deno, but the portable controlled hook does. External gate tools retain their prerequisites. MIT, André's tag authorization and isolated exact-artifact promotion remain; the npm-specific OIDC/provider exception does not.

## Trade-offs

- Keeping the Node bootstrap while migrating only the product was recommended and declined: the confirmed operational boundary includes protected bootstrap. It costs a separately authorized/proved port before product admission, not an extra task inside ticket 01.
- Replacing checker/tests/mutation/lint was declined. Supplemental complete-graph `deno check` complements primary tsrs and nonblocking `tsc` drift. Deno's compiler/ambient model and the retained Node test hosts require explicit compatibility evidence.
- npm plus an independently provisioned Deno launcher was initially selected, then explicitly withdrawn **for v0**. Source/assets and compiled releases avoid that two-runtime user-facing launcher. This does not authorize unpublishing the existing placeholder or promise a later npm/JSR channel.
- Native-only APIs were not required: stable Web/Deno and supported `node:` built-ins are allowed. JSR `@std`, npm/HTTP or vendored runtime libraries remain forbidden; embedding them would not remove their supply-chain cost. The selected Deno engine is itself a runtime supply chain, not an imported product library.
- Permission prompts, `-A`/`--allow-all`, broker-driven/automatic escalation, ambient reconfiguration and subprocess-sandbox claims were rejected. After [source investigation](../../.scratch/superman-v0/deno-capability-research.md), **Q23 explicitly permits reviewed broader read/write/run/net classes where required for portable binaries**, revising Q9's blanket narrow-grant wording. Fixed profiles cannot dynamically accommodate arbitrary external resources under no-prompt. Per-deployment recompilation was considered but not selected. Do not call the selected portable profile repository least privilege; source/hooks/bootstrap are scoped more tightly where feasible. Exact grants remain Gate 1 blockers. Deno grants do not establish host/credential isolation; the reconciled §8/ADR 0015 use existing self-hosted environments with bounded safeguards/residual limits, not a new VM or attestation prerequisite.

## Implementation and evidence boundary

This ADR is **interview-confirmed design, not activated policy**. At the November 1 synthesis, no Deno numeric pin, exact grant profile, checker integration, mutation bridge, complete four-metric collector or platform pass had been accepted. Subsequent preparation acceptances retain the scopes recorded in [the preparation record](../../.scratch/superman-v0/gate1-preparation.md); documented upstream capability is not repository verification. In particular, the November 2 mutation bridge was accepted at local darwin-arm64 fixture scope, not as operational-graph/native-matrix admission.

Q24 requires full-Deno source/hook/compiler startup controls neutralized **before runtime entry**, not a claim that app-level env checks reverse startup effects. The OS-launch mechanism and route-specific denort behavior need separate fixtures. Q21 requires protected MIT/release-assets/build-manifest adoption after 10 and before 33, avoiding a release-license cycle; workflow/uploader activation still follows 11. Q22 preserved concurrent code-quality work during Deno planning. The subsequent [combined reconciliation](../../.scratch/superman-v0/code-quality-planning.md) aligns the approved backlog delta; no execution evidence or ticket admission follows from that work.
